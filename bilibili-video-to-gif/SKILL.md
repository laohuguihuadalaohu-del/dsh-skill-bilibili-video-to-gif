# B站视频 → GIF 动图

一条已经跑通的完整链路：**取 cid → 取直链（镜像回退）→ 抽帧定位 → 转 GIF → 自检**。
三个脚本在 `scripts/`，依赖只有 `curl`、`ffmpeg`、`python3` + Pillow。

## 什么时候用

- 用户要"给素材包补几张动图"、把视频名场面做成 GIF、做表情包。
- 只给了 BV 号或视频链接，要拿到可截取的本地文件。
- 用户说"yt-dlp 下 B站报错 412"、"GIF 好几 MB 太糊/太大"。

不适用：长视频归档下载（用专门的下载工具并注意平台条款）、需要音轨的内容、视频重新剪辑合成。

## 关键判断：不要用 yt-dlp

`yt-dlp` 会先抓 B站播放页 HTML，而非浏览器 UA 一律返回 **HTTP 412**，带 cookie/UA 也救不回来。
**正确做法是根本不碰播放页，只走 `api.bilibili.com`**，再用镜像换域名拿二进制。这条路稳定且免登录。

## 四步流程

### 1. 下载

```bash
python3 scripts/bili_fetch.py BV1T8J66CEEu -o downloads          # 默认 360p
python3 scripts/bili_fetch.py BV1T8J66CEEu -o downloads --qn 32  # 480p
```

脚本做的事：`x/web-interface/view` 取 cid → `x/player/playurl?qn=16&fnval=0` 取 durl →
把直链域名换成 `upos-sz-mirror{ali,cosov,hw}.bilivideo.com` 逐个试 → 校验文件头 `ftyp` 才算成功。
失败会自动重试 4 轮（每次重新取 token）。

> `qn`：16=360p，32=480p，64=720p。更高清晰度需要登录态，360p 对 GIF 已经够用（GIF 最终只输出 400px 宽）。

### 2. 定位时间点（不要盲截）

```bash
python3 scripts/frame_sheet.py downloads/BV1T8J66CEEu.mp4 -i 4 -o sheets
```

输出带秒数标注的拼版 PNG。**用图片查看工具读这些 PNG**，挑出想要的动作区间。
一次性拿到整片的时序，比反复试探 `-ss` 快得多，也避免截到黑帧、片头字幕卡。

间隔怎么选：先 `-i 8` 看全片节奏，再对候选区间 `-i 1` 精确定位。确认关键画面后，用
`ffmpeg -ss <t> -i in.mp4 -frames:v 1 -y check.png` 抽单帧复核，再正式截取。

### 3. 转 GIF

```bash
./scripts/to_gif.sh downloads/BV1T8J66CEEu.mp4 34 5 out/街头群舞.gif 400 10 64
#                               视频            起点 时长 输出            宽  fps 色数
```

脚本用**两遍调色板法**（`palettegen` + `paletteuse`），生成后自检帧数与尺寸。
直接 `ffmpeg -i in.mp4 out.gif` 会得到发灰、边缘锯齿严重的结果，不要用。

### 4. 批量与命名

命名带内容描述而不是纯序号，例如 `07_宇宙尽头是铁岭横幅_BadGuy.gif`，配一份索引
（来源 BV 号 + UP主 + 截取秒数 + 版权说明）。素材包给他人使用时，索引比动图本身更重要。

## 参数经验（实测）

| 参数 | 推荐 | 说明 |
| --- | --- | --- |
| 时长 | **3–5 秒** | 超过 5 秒体积翻倍、信息量不增；表情包 2–3 秒足够 |
| 宽度 | 400px | 微信/网页场景够用；720px 体积约为 3 倍 |
| fps | **10** | 比 12 省约 20% 体积，肉眼看不出差别 |
| 色数 | 64 | 96 更干净但体积 +30%；人脸特写建议 96 |
| 单条体积 | 目标 ≤ 2MB | 400px/10fps/5s/64 色 ≈ 1.5–1.9MB |

体积压不下去时，优先砍时长，其次砍宽度，最后才动 fps 和色数。

## 坑

1. **412 风控**：见上，绕开播放页。若连 API 也 412，说明 IP 被临时限流，等几分钟或换网络。
2. **CDN 403 `Access Denied`**：直链落在 `*.akamaized.net` 时必现。换 `bilivideo.com` 镜像即可，签名串对 host 不敏感。
3. **下载"成功"但文件是 HTML**：一定要校验 `ftyp` 文件头，否则后面 ffmpeg 报 `moov atom not found`。
4. **PIL 保存 GIF 会自动去重相同帧**：自己用 Pillow 画动图时，连续重复帧会被合并，动画变卡顿。改用"唯一帧 + 逐帧 `duration` 列表"表达停顿。
5. **不要指望表情包站**：`fabiaoqing.com` 很快风控（HTTP 000/412）；`doutula.com` 能下但搜索是模糊匹配——搜"范德彪"给二战纪录片、搜"谢广坤"给通用"谢谢"表情包。人物类表情包要么自制，要么从授权视频截。
6. **B站水印**：截取画面自带水印和 UP主 ID。可 `crop=iw:ih-24:0:0` 裁掉，但那样也丢了署名，不建议。

## 版权与署名（必须处理）

- 截取动图是 **UP主的作品**，不是"网上找的图"。发布前要么获授权，要么以引用评论方式使用。
- 涉及真人的 AI 换脸/仿声内容，还可能叠加肖像权、声音权问题（《民法典》声音参照肖像权保护）。
- 素材包里**务必**记录：BV 号、UP主、原始标题、截取秒数、采集日期、版权状态。
- 自己用文字/图表生成的动图无此问题，优先自制再考虑截取。

## 自检清单

- [ ] 文件头是 `ftyp`，ffmpeg 能读
- [ ] GIF 帧数 > 12，动作连贯，无黑帧
- [ ] 单条 ≤ 2MB，宽度与用途匹配
- [ ] 关键画面（字幕/横幅/表情）在 GIF 内实际出现过——**必须抽帧复核，别只看起始帧**
- [ ] 索引里记了 BV 号、UP主、秒数、版权状态
